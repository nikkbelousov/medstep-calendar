# AGENTS.md

## Назначение проекта

Это локальное Vite + React + TypeScript приложение для отслеживания одного пользовательского плана постепенного снижения препарата.

Приложение показывает:

- дату старта;
- плановые дни приёма, пропуска или приёма по требованию;
- пользовательские названия препарата, дозы, времени, поддержки и резерва;
- отметки выполнения;
- симптомы;
- заметки;
- прогресс по плану.

Приложение не является медицинским инструментом принятия решений. Оно только отображает заданный пользователем или согласованный с врачом план.

## Текущий статус

Phase 1 завершена: фиксированный исходный календарь был восстановлен как локальное приложение.

Phase 2 является текущей базой: приложение стало настраиваемым календарём с одним активным планом.

Текущие возможности:

- настройка даты старта;
- выбор препарата из нейтрального списка или ввод своего названия;
- настройка дозы и времени;
- настройка названий поддержки, резерва и симптомов;
- пресеты схем;
- собственная повторяющаяся последовательность дней;
- сохранение в `localStorage`;
- миграция старых локальных отметок.

## Storage

Основной ключ:

- `taper-calendar-v2`

Legacy key:

- `omez-taper-calendar-v1`

Legacy key нужен только для чтения старых локальных отметок при миграции. Не удаляй его автоматически и не показывай пользователю как часть публичного UI.

Публичные тексты не должны ссылаться на старый прототип. Используй нейтральные формулировки вроде “базовый план”, “настройки плана”, “сбросить настройки плана”.

## Архитектура

Текущая структура:

- `src/App.tsx` — состояние приложения и layout;
- `src/lib/date.ts` — date helpers;
- `src/lib/plan.ts` — типы, пресеты, расчёт планового дня;
- `src/lib/storage.ts` — сохранение, загрузка и миграция storage;
- `src/styles.css` — Tailwind и общие component classes.

Держи структуру простой. Выноси компоненты только если файл стал реально тяжёлым или изменение становится трудно проверять.

## Правила реализации

- Делай маленькие, проверяемые изменения.
- Не рефактори, не переименовывай и не форматируй несвязанный код.
- Не меняй продуктовую модель молча.
- Если есть риск значительной переделки из-за неоднозначности, задай вопрос.
- Если можно сделать безопасное предположение, продолжай и коротко укажи его.
- Используй строгие типы TypeScript там, где это практично.
- Избегай `any`; если он временно нужен, оставь короткий комментарий почему.
- Не удаляй пользовательские записи при изменении даты старта или схемы: records привязаны к ISO-дате.
- Полный сброс всех данных должен быть отдельным опасным действием с явным подтверждением.

## Date Handling

Не добавляй тяжёлые date-библиотеки.

Используй helpers:

- `toISO`;
- `fromISO`;
- `addDays`;
- `dayDiff`;
- `getMonthMatrix`.

Даты хранятся как ISO strings: `YYYY-MM-DD`.

Календарь должен оставаться Monday-first.

## UX

UI должен быть:

- простым;
- спокойным;
- читаемым;
- понятным на desktop;
- пригодным для mobile;
- без медицински пугающей визуальной стилистики.

Не перегружай главный экран техническими деталями. Публичные тексты должны быть нейтральными.

## Medical Safety Rules

Приложение не должно действовать как врач.

Запрещено реализовывать:

- автоматические рекомендации дозировки;
- диагнозы;
- советы “нужно принять/отменить/изменить препарат”;
- drug interaction claims;
- emergency triage кроме общей нейтральной safety copy;
- AI-generated medical advice;
- новые рекомендации по лечению, дозировкам, времени приёма или rescue-medication.

Разрешено:

- отслеживать пользовательский план;
- показывать пользовательские названия препаратов;
- показывать только заранее заданные напоминания из плана;
- записывать симптомы;
- экспортировать данные для обсуждения с врачом, если эта функция будет добавлена позже.

Обязательный смысл дисклеймера:

```text
This app is a personal tracking tool. It does not provide medical advice, diagnosis, or treatment recommendations. Medication changes should be discussed with a qualified healthcare professional.
```

## Environment

Среда разработки:

- OS: Windows 11;
- Editor: VS Code;
- Shell: PowerShell или Git Bash;
- пакетный менеджер: `pnpm`.

Windows/local browser notes:

- Для foreground-команд используй `pnpm install`, `pnpm dev`, `pnpm build`.
- Если запускаешь долгий dev server через PowerShell `Start-Process`, используй `pnpm.cmd`, а не bare `pnpm`.
- Предпочитай `pnpm dev --host 127.0.0.1 --port 5173`.
- Если порт занят, сначала проверь существующий dev server, не считай это блокером.
- Для routine localhost UI-проверок используй Codex in-app browser, если он доступен.
- Используй `http://127.0.0.1:5173/` как основной URL для локальной проверки.
- Не используй Playwright CLI для routine UI-проверок, если in-app browser работает.
